# DBCheck v26.8.20.0 发版说明

**发布日期**：2026-08-20
**版本号**：v26.8.20.0
**分支 / 提交**：`origin/main` @ `d1785cd`（含 `d0e3950` MySQL 系报告修复、`ccc63bf`/`485ee2d` JDBC 统一接入、`74a8715`/`1973aa5` 驱动版本选择）

---

## 一、概述

v26.8.20.0 的核心是 **JDBC 统一连接层 + 驱动版本管理**，并修复了一批 **MySQL 系巡检报告**问题：

- **JDBC 统一连接层（重磅）**：新增 `modules/jdbc_connector.py`，把分散在各巡检入口的连接逻辑收口为统一层；连接测试与 8 类 JDBC 巡检全部隔离到**干净子进程**执行，根治 gevent 下进程内 JVM/JPype 引发的界面卡死与死锁；
- **16 类数据库统一 JDBC 接入**：PG 系（PostgreSQL / IvorySQL / Kingbase / MariaDB / OceanBase / TiDB / YashanDB 等）与 MySQL 系批量收口到统一连接层，连接串构造、驱动解析、子进程隔离行为一致；
- **JDBC 驱动版本选择**：`driver_registry` 按版本解析驱动 jar，5 个 JDBC 插件 `driver_version` 透传横向铺开，DM / GBase 接入驱动管理，修复 clickhouse / uxdb 测试路由；
- **MySQL 系巡检报告修复**：InnoDB 表空间列表 + 数据库级别权限章节去掉「行转列」，每条记录一行展示；修复 MySQL 巡检 `INNODB_TABLESPACES` 查询失败（Unknown table，运行时按版本自适应探测 modern / legacy 表名）；
- **打包与 Docker 修正**：P0/P1 打包与 Docker 脚本修正，清理临时脚本并新增 `_tmp_*` 忽略规则。

> 提示：本次改动涉及 `modules/`、`plugins/available/`、`web_templates/index.html` 与构建配置，**若以打包产物（exe / Docker 镜像）分发，请重新构建使最新源码生效**；产品版本标记已对齐到 v26.8.20.0。

## 三、主要变更说明

### 1. JDBC 统一连接层（485ee2d / ccc63bf）

- 新增 `modules/jdbc_connector.py`：统一 URL 构造、连接参数归一、驱动 jar 解析、连接测试入口；
- 连接测试（`jdbc_test_cli`）与巡检采集（`jdbc_inspection_cli`）全部走**干净子进程**，未被打 gevent 补丁，杜绝进程内起 JVM / JPype 原生线程钉死事件循环的问题；
- 16 类数据库统一 JDBC 接入：PG 系（PostgreSQL / IvorySQL / Kingbase / HGDB / UXDB）、MySQL 系（MySQL / MariaDB / OceanBase / TiDB）及 DB2 / ClickHouse / SQL Server / Oracle / DM / GBase 等巡检入口收口到统一层；
- 定时巡检（`scheduler.py`）对 JVM 类型同样子进程隔离，避免定时任务卡死拖垮主进程。

### 2. JDBC 驱动版本选择（1973aa5 / 74a8715 / d1785cd）

- `driver_registry` 新增按版本解析驱动 jar 的能力（`get_driver(db_type, version)` / `resolve_jdbc_driver_jars`）；
- 5 个 JDBC 插件（oracle / sqlserver / hgdb / uxdb / db2 等）`driver_version` 形参透传横向铺开，数据源与巡检链路一致；
- DM / GBase 接入驱动管理，前端巡检表单支持驱动版本下拉；
- 修复 clickhouse / uxdb 测试路由与 `driver_version` 前向兼容；
- 驱动管理模块整体调整（驱动目录按 版本 子目录组织、上传 / 删除 / 恢复）。

### 3. MySQL 系巡检报告修复（d0e3950）

- **去行转列**：`modules/inspection/engine.py` 的 `force_horizontal_table_keys` 加入 `innodb_tablespaces` / `innodb_datafiles` / `db_privileges`，InnoDB 表空间列表与数据库级别权限章节不再竖排为「字段:值」卡片，改为每条记录一行（横向表）；
- **查询失败修复**：`modules/entrypoints/main_mysql.py` 新增 `_resolve_innodb_table()` 运行时探测——`INNODB_TABLESPACES` / `INNODB_DATAFILES` 仅 MySQL 8.0.21+ 存在，5.7 / 8.0 早期为 `INNODB_SYS_TABLESPACES` / `INNODB_SYS_DATAFILES`，以「能否真正 SELECT」为准自动选表；两者皆不可用时降级返回空集并附说明，不再报 `Unknown table` 跳过章节。

### 4. 打包 / Docker 修正（7f84b0d / f77ceb8）

- P0/P1 打包与 Docker 脚本修正（`deploy/Dockerfile` / `docker-entrypoint.sh` / `web_ui.py`）；
- 清理临时脚本，`.gitignore` 新增 `_tmp_*` 忽略规则。

## 四、升级与迁移注意事项

1. **无需数据迁移**：本次不涉及核心库结构或配置格式破坏性变更；驱动目录按版本子目录重组后，`driver_registry` 会按版本解析，老配置缺省版本自动回退到默认 jar。
2. **重启常驻 Web 服务 + 硬刷新浏览器**：涉及 `web_templates/index.html` 与 `modules/`，升级后请重启服务并 `Ctrl+F5` 强制刷新。
3. **重新构建分发物**：含源码改动与构建配置变更，若以 exe / Docker 镜像分发，**必须重新运行构建脚本后再发布**，否则旧产物仍走老连接逻辑。
4. **驱动 jar 布局**：驱动管理按「版本子目录」组织（如 `drivers/oracle/<version>/`），升级前如本地驱动目录是旧平铺布局，可在驱动管理界面重新上传或让 `driver_registry` 自动兼容旧路径。
5. **版本标记对齐**：产品版本标记已统一更新到 v26.8.20.0（`modules/config/version.py` / `version.json` 等），发布时直接打 tag 即可。
